# 栄冠は君に 甲子園の鼓動 2002／2004 - 不具合修正パッチ

PS2「栄冠は君に 甲子園の鼓動」の2002年版・2004年版を **PCSX2** で遊ぶときに起きる、**試合に入る時に画面が止まる（音楽だけ鳴り続ける）不具合**の修正パッチです。おまけとして、**スカウト候補者を全員入部させるチート**も入っています。

| 対象ソフト | 型番 | CRC | パッチファイル |
|---|---|---|---|
| 栄冠は君に2002 ～甲子園の鼓動～ | SLPS-20184 | `B643BEA8` | `SLPS-20184_B643BEA8.pnach` |
| 栄冠は君に2004 ～甲子園の鼓動～ | SLPS-20379 | `046A7706` | `SLPS-20379_046A7706.pnach` |

> **CRCについて**: CRCはディスクイメージの中身から計算される値で、パソコンやユーザー環境には依存しません。同じゲーム・同じバージョンなら、誰の環境でも同じ値になります。PCSX2のゲーム一覧でゲームを右クリック →［プロパティ］→［概要］で確認できます。上の表と違う場合、このパッチは読み込まれません。

## 収録内容

どちらのファイルにも、次の3つが入っています（2作品で共通の名前です）。PCSX2の［パッチ］タブで個別にオン・オフできます。

| 名前 | 種類 | おすすめ |
|---|---|---|
| 修正1: 試合に入る時のフリーズ・クラッシュ（主な原因） | 不具合修正 | **必ず有効に** |
| 修正2: 試合に入る時のフリーズ（別の原因） ※修正1と一緒に有効化 | 不具合修正 | **必ず有効に** |
| チート: スカウト候補者を全員入部させる | チート | お好みで |

### 修正1・修正2：試合に入る時のフリーズ

試合（練習試合・公式戦とも）の読み込み中に画面が止まり、音楽だけが鳴り続ける不具合です。PCSX2のログに `TLB Miss` などのエラーが出ることもあります。作者の環境（2004版）では、修正前は試合に入るたびにおよそ2回に1回の割合で止まっていました。

同じ症状に見えますが、原因は2つあります。

- **修正1（主な原因）**: ゲームの通信処理が、作業用の領域（112バイト）より大きいデータを受け取ったときに領域をはみ出して書き込み、処理の戻り先を壊していました。受け取る量を領域の大きさまでに制限します。通常の大きさのデータでは、元とまったく同じ動作です。
- **修正2（別の原因）**: 壊れたデータ（大きさの欄が0）が届いたとき、ゲームが次の受信の準備をしないまま処理を終えるため、それ以降の通信がすべて止まっていました。壊れたデータの中身から本来の返事を特定できればそのまま処理し、受信が止まっていれば再開させます。早送り（ターボ）を多用していると起きやすいようです。

**2つとも有効にしてください。** 修正1だけでも大半は防げますが、修正2の原因による停止は修正1では防げません。

### チート：スカウト候補者を全員入部させる

冬のスカウトで提示された候補者（3〜4人）を、誰を選んだかに関係なく、4月の入部処理で全員入部させます。

- スカウトした選手は通常の新1年生の枠と入れ替わりで入るため、**新1年生の人数は変わりません**
- **4月の入部処理より前に**有効にしてください（冬のスカウトの後でも、4月より前なら間に合います）
- 新1年生の枠が候補者より少ない場合、入りきらない候補者は入部しません。上級生が上書きされることはありません（設計上の動作で、実際にこの状況になった例はまだありません）
- ゲームバランスが変わるので、本来の遊び方をしたい場合はオフのままにしてください

## 導入方法（PCSX2）

1. PCSX2の［設定］→［フォルダー］で、「パッチ」フォルダーの場所を確認します（通常は `ドキュメント\PCSX2\patches`）
2. 遊ぶゲームの `.pnach` ファイルを、**ファイル名を変えずに**そのフォルダーへコピーします
3. ゲーム一覧でゲームを右クリック →［プロパティ］→［パッチ］タブを開き、「修正1」「修正2」にチェックを入れます（チートを使う場合はそれもチェック）
4. **PCSX2をいったん完全に終了してから**、ゲームを起動し直します（リセットだけでは反映されないことがあります）
5. ログウィンドウを開いている場合、`Enabled patch: 修正1: …` の行と「3 ゲームパッチが有効です」（チートなしなら「2」）が表示されれば適用されています

> ［パッチ］タブで、修正2だけ「Applied: Unknown」と表示されます。これは修正2が「起動時に1回だけ書く部分」（動作記録の初期化）と「毎フレーム書く部分」の両方を含むためで、正常です。

## 動作確認

**修正1**
- 2002版: 試合入り10回連続で停止なし
- 2004版: 試合入り10回連続で停止なし

**修正2**
- 2002版: 約1時間半・約12試合のプレイ中に2回作動し、止まった受信を復旧（停止なし）
- 2004版: 実際に止まったゲームに同じ処理を施して復旧できることを確認。有効にした状態でのプレイで停止・副作用なし

**チート**
- 2002版: 4年分のスカウトで、候補者12人全員が入部
- 2004版: 候補者4人全員の入部を2回確認

**共通**
- 確認したPCSX2: 安定版 v2.8.2、開発版 v2.9系
- どちらのバージョンでも、パッチの書き換えがゲームのメモリに正しく反映されていることを、PCSX2のメモリ読み出し機能（PINE）で1行ずつ照合済みです

## 技術的な詳細

2002版と2004版は同じソースから作られていて、命令の並びは同じで、アドレスだけが違います。

| 箇所 | 2002版 | 2004版 |
|---|---|---|
| 通信（SIF0）受信の割り込み処理 | `0x0027FCF8` | `0x0027FD78` |
| 修正1の書き換え（3命令） | `0x0027FD30`〜`0x0027FD38` | `0x0027FDB0`〜`0x0027FDB8` |
| 修正2の入口（大きさ0の分岐） | `0x0027FD20` | `0x0027FDA0` |
| 修正2の入口（返事処理） | `0x002801D0` | `0x00280250` |
| 修正2の本体 | `0x00270620`〜 | `0x00270680`〜 |
| 修正2の動作記録 | `0x002707F8`〜 | `0x00270858`〜 |
| チートの呼び出し差し替え | `0x00116474` | `0x00116464` |
| チートの上級生上書き防止 | `0x00114EB4` | `0x00114EA4` |
| チートの本体 | `0x0024C4C4`〜 | `0x0024C524`〜 |

**修正1**: 割り込み処理は144バイトのスタック領域を使い、+112にs0、+128に戻り先（ra）を退避しています。受信パケットの大きさ（1バイト、最大255）から「(大きさ+15)÷16」個の16バイト単位をスタック先頭にコピーするため、大きさが112を超えるとs0が、128を超えると戻り先が壊れます。コピー数を7（112バイト）までに制限しました。

**修正2**: パケットの大きさの欄が0だと、元の処理は次の受信のためのDMA設定（iSifSetDChain）をせずに終わるため、SIF0の受信が止まり、以後のRPCの返事が届かなくなります（同期呼び出しが永久に待ち続ける）。修正2は、壊れたパケットの後半に残っている情報（依頼元・依頼の種類・依頼書が使用中か）から待っている依頼を特定できれば、その返事として処理します。さらにDMAが止まっていれば受信を再開します。あわせて返事処理の入口で、待っている依頼のない重複した返事を無視します。本体は、ゲーム内でどこからも呼ばれていないSDR用RPCサーバーの領域に置いています。

動作記録は、先頭のワードが `56394F4B` のとき有効です: +0x4 大きさ0のパケット数、+0x8 返事を救出した回数、+0xC 受信を再開した回数、+0x10 重複した返事を無視した回数、+0x14 最後に起きたフレーム、+0x18〜 最後の壊れたパケットの内容。

**チート**: 4月の入部処理は、選ばれた候補者1人について入部関数を呼びます。その呼び出しを、候補者全員分をくり返すループに差し替えました。入部関数は「最初の1年生の枠」を上書きする作りのため、上書きした枠に一時的な目印を付けて次の回で選ばれないようにし、最後に目印と選択番号を元に戻します。本体は、どこからも呼ばれていない関数の領域に置いています。
